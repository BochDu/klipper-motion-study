# 学习记录（按日期）

## 约定

- 一天一篇，文件名 `YYYY-MM-DD.md`（当天没学就不建文件，不补空白）。
- 只记：**知识点结论 / 对应源码位置 / 可复现的实测片段**；完整代码不抄，贴关键行号与符号。
- **「关键发现」最多 3 条**，只写改变认知的结构性洞察（分层边界、时间/数据模型、精度根基）。
  零散数值、公式验算、文件名差异一律归入「做了什么」；宁可少写，不塞流水账。
- 每篇固定五段，写不满可留空但要保留标题（**自测段不可省略**）：

```markdown
## 今日目标
## 做了什么
## 关键发现
## 自测
## 下一步
```

- 命令与输出贴「可复现的最小片段」，方便以后回溯。
- 涉及源码位置时用 `路径:行号 符号` 的形式，例如 `klippy/toolhead.py:120 LookAheadQueue`。

### 每日讲解顺序（先知识点，再结合代码）

- 「做了什么」按固定三步写：
  1. **知识点**：结论先行，一句话一条规则，先讲「是什么 / 怎么判断」，不先铺推导。
  2. **结合代码**：把每条知识点落到 `路径:行号 符号`，用源码验证结论，而不是只贴日志；
     每天至少覆盖一处 `klipper/` 子模块源码，行号按版本锚点 `0cee841` 核对。
  3. **实测**（可选）：可复现的最小命令与输出，用来验算数值。
- **不设「卡点与处理」段**：后面是学习阶段，有不理解就当场解决，解决完直接写进知识点，
  不把排障过程留在笔记里。

### 自测段规范（每日必填）

自测是**当天的唯一验收标准**：答不上来就回去看源码与实测数据，不许直接翻篇。

- 出 **3 道**题，必须**可证伪**：能落到源码行号、公式验算、日志数值，或「改某个参数后数值会变成多少」的推演；不写「谈谈你的理解」这类无法判分的题。
- 每题附**答案**，或明确的回看指向（如「答不上来回去看 `docs/dataflow.md` 第 4 节」）；答案优先用当天实测数据，不靠背结论。
- 三题固定覆盖三个角度：**① 数据结构 / 接口 ② 物理含义 / 公式 ③ 改参数后的推演**（迁移题，检验真懂而非记住）。
- 自测暴露的盲点，写进 `## 下一步` 的第一条。
- 教学时由助手先出题、学员作答；学员未作答时，助手给出答案并一起落进当天笔记。

模板（答案紧跟题目，便于回看）：

```markdown
## 自测

1. 题目？（答不上来回去看 `docs/xxx.md` 第 N 节）
2. 题目？
3. 题目？

### 参考答案

1. ...
2. ...
3. ...
```
