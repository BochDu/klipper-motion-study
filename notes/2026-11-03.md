## 关键发现

1. **分层地基：上位机定死时间轴，MCU 只到点翻转**。规划层交付的是「笛卡尔空间 + 统一打印时间轴」上的
   `accel_t/cruise_t/decel_t + start_pos + axes_r + v0/vc/a`，不是点位序列；各轴 step 时刻的求解
   （`itersolve`）也在上位机 C 侧完成。MCU 只拿到 `interval/count/add`，做
   `next += interval; interval += add`。**两端都不做对方的事**。
2. **step 时间是绝对时间戳，不是「再延时多久」**。首个 `interval=5040825` tick = **0.252 s**
   （0.25 s 提前量 + 起步 0.002 s），含义是"打印开始后第 0.252 秒迈第一步"；
   时钟同步是整条链路的精度根基。
3. **规划层永远领先 MCU 至少 0.25 s**（`BUFFER_TIME_START`，`print_time` 从 0.25 起算）。
   这个提前量是分层架构成立的前提，也是丢步 / 抖动 / 提前减速 / 输入停滞几类问题的共同根源。

### 参考答案

1. 见 `docs/dataflow.md` 第 4 节的 14 参数表：`tq`、`print_time`、`accel_t/cruise_t/decel_t`、
   `start_pos_x/y/z`、`axes_r_x/y/z`、`start_v`、`cruise_v`、`accel`。
   传三段时长而非点位，是因为 `pos(t)` 是解析函数、一次 append 的开销与步数无关（最多 3 个 `struct move`），
   且离散化推迟到插补线程的 `itersolve`，各轴共享同一时间轴而天然同步。
2. `interval` = 相邻两步的 MCU 时钟 tick 数；`count` = 该批次步数；`add` = `interval` 的逐阶增量
   （二阶近似加速度，MCU 执行 `next += interval; interval += add`）。
   匀速段速度恒定 ⇒ 相邻间隔不变 ⇒ `add=0`（加速 `add<0`、减速 `add>0`，见解码日志）。
3. `steps_per_mm = 200×16/40 = 80`，`F3000 = 50 mm/s` ⇒ `4000 step/s`，
   `20 MHz / 4000 = 5000 tick`。改 `microsteps=32` ⇒ `160 steps/mm` ⇒ `8000 step/s`
   ⇒ **`interval = 2500`**（减半），且总步数 4000 → 8000，`count` 累计翻倍。
   已用 `/tmp` 临时配置实测：`queue_step oid=2 interval=2500 count=7868 add=0` ✓
   （详见 `docs/dataflow.md` 4.1，工作区配置未改动）。
