# 2026-11-05

## 知识点

1. **G-code 里的 `X50` 不是最终位置，`last_position` 才是**：`G90` 下
   `last_position[i] = v + base_position[i]`；`G91` 下 `last_position[i] += v`；
   `G92` 只写 `base_position[i] = last_position[i] - offset`，机械位置一动不动。
2. **`F` 的 ÷60 藏在 `speed_factor` 里，不在 `cmd_G1`**：初始化为 `1./60.`，
   `self.speed = F * speed_factor` 直接得到 mm/s；`M220 S` 会改这个因子，
   所以同一个 `F` 在不同倍速下 `self.speed` 不同。
3. `GCodeMove` 只做坐标 / 倍率变换，把 `last_position` 与 `speed` 交给
   `move_with_transform`（默认即 `toolhead.move`）；`ToolHead.move` 以
   `commanded_pos → newpos` 构造 `Move`，`move_d == 0` 直接返回、不入队。

## 关键发现

1. G-code 坐标与机械坐标是两套数：`G92` 只挪零点（`base_position`），
   `last_position` 才是真正下发的位置；`G90` / `G91` 只决定 `v` 加到哪个基准上。
2. 单位换算不在解析 G1 的地方，而在 `speed_factor`；倍率（`M220`）与 `F` 因此解耦，
   同一个 `F` 可以对应不同的 `self.speed`。
3. 变换层不产生运动，只交出「目标位置 + 速度」；`Move` 由规划层用
   `commanded_pos → newpos` 构造，零长度 move 在入队前就被丢弃——两层职责分明。
