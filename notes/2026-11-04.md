## 做了什么

### 1. 极简核心（1-1 讲解重写版）

**必须死记**

1. 上位机定死时间轴，MCU 只到点翻转：规划层交 **14 个数**（三段时长 / 起点 / 方向 / 速度），
   MCU 收 **3 个数**（`interval/count/add`）。两端都不做对方的事。
2. step 时间是**绝对时间戳**，不是「再延时多久」：20 MHz tick，`5040825 = 0.252 s`。
3. 规划层永远领先 MCU **≥ 0.25 s**（`BUFFER_TIME_START`）。

**一条 G1 的 5 次变形**

```
G1 X50 F3000
 ① cmd_G1        50 mm/s                             (F ÷ 60)
 ② Move          0.016667 / 0.983333 / 0.016667 s    (加速/匀速/减速)
 ③ trapq_append  t = 0.25 s，14 个数，没有点位
 ④ queue_step    interval = 5000 tick = 0.25 ms，add = 0
 ⑤ MCU           next += interval; interval += add，重复 count 次
```

**3 个判断标准**（今天真正要拿走的东西）

| 要判断什么 | 只看 | 规则 |
| -- | -- | -- |
| 匀速段每步间隔 | 巡航速度 + 每毫米步数 | `interval = CLOCK_FREQ / (v × steps_per_mm)` |
| 第一条脉冲时刻 | `half_step` + 加速度 | `t = √(2·half_step / a)`，再加 0.25 s |
| 加速 / 匀速 / 减速 | `add` 的符号 | `<0` 加速；`=0` 匀速；`>0` 减速 |

👉 **改 `F` 只动间隔，不动首步；改 `microsteps` 才动首步。**

**误区纠正**

1. ❌ `interval` 是延时 / 脉宽 → ✅ 是相邻两个上升沿的间隔（两个绝对时刻之差）
2. ❌ MCU 算速度和插补 → ✅ 只做整数加法与引脚翻转
3. ❌ 规划层把 4000 个点位发给 MCU → ✅ 只发 14 个数，`pos(t)` 现算
4. ❌ `F` 翻倍首步也跟着变 → ✅ 不变，起步由 `half_step` 和 `a` 决定
5. ❌ `add` 是加速度 → ✅ 是 `interval` 的逐阶增量（tick/步，二阶近似）

**四句口诀**：上位机写谱，MCU 抬手 / 时间是绝对，不是延时 /
间隔看速度，首步看半步 / 提前四分一，链路才不断。

结论不是背来的：`add` 的符号、首步时刻、绝对时钟，都能在上面这些行里直接读到。

**源码链条**：`step_time` 从哪来（按调用顺序，全在 `klipper/` 子模块）

1. `klippy/stepper.py:31`：`step_dist = rotation_dist/steps_per_rotation = 40/(200×16) = 0.0125 mm`；
   `:234-235` 由 `itersolve_set_trapq()` 传给 C。
2. `klippy/chelper/itersolve.c:33` 取半得 `half_step = 0.00625`；`:42` 首个
   `target = commanded_pos + half_step = 0.00625 mm`。
3. `:46-52` 割线法猜 `t`（循环展开见下方「求根循环」）。位置公式两处：
   `kin_cartesian.c:14-19` 返回 `move_get_coord(m,t).x`，`trapq.c:24-28` 是
   `(start_v + half_accel·t)·t`；本例 `start_v=0`、`half_accel=1500` ⇒ `x=1500t²`
   ⇒ 反解 `t = √(target/1500)`。
4. `:107-111`：`stepcompress_append(sc, sdir, m->print_time, guess.time)` ——
   **第 4 个实参 `guess.time` 就是 `step_time`**，是「从 move 起点算的第几秒」而非耗时；
   紧接着 `target += half_step+half_step`（一整步）⇒ 下个阈值 `0.01875 mm`。

代入：`0.00625 → 0.002041 s`、`0.01875 → 0.003536 s`、`0.03125 → 0.004564 s`。
位移 3 倍、时间只 √3 倍，因为加速段位移 ∝ `t²`；这些 `t` 是累积值，相减才是步间隔。

**求根循环**：`klippy/chelper/itersolve.c:46-123`，整个函数只有一个 `for (;;)`

- 四段：① `:47-51` 割线法猜 `next_time` ② `:52-68` 越界时二分兜底 / 指数扩张上界
  ③ `:69-73` `guess.time = next_time` + `guess.position = calc_position_cb(...)`
  —— **唯一把 t 代进位置公式的地方** ④ `:74-105` 误差 `>1e-9` 就更新上下界并 `continue` 回去再猜。
- **公式不动、动的是 t**：`x=1500t²` 一行未改，`:71` 的 `guess.time` 反复变；
  同一个 `target` 内由 `:104` 逼近，命中后 `target` 才跳一格。
- 找到一步**不退出**：`:107-122` 提交 `guess.time`、`target +=` 一整步、重置上下界，
  自然回到 `:46` 找下一步 ⇒ 一次调用算完整个时间窗口的所有 step，不是每步调一次函数。
- 唯一 `break` 在 `:58-60`：`guess.time >= end`（`end = abs_end - m->print_time`，`:34`）；
  退出后 `:124` 把 `commanded_pos` 对齐到最后一步，供下次调用接续。

**重点行拆解**：`klippy/chelper/stepcompress.c:508-534 stepcompress_append`

整个函数只有三块：① `:512-514` 算绝对时刻 ② `:516-529` 处理「上一格」 ③ `:531-532` 占住「这一格」。
它不生成报文、不更新 `last_step_clock`、通篇没有 `interval`。

- **第一次调用（第一步）**：`step_time=0.002041 s` → `step_clock=5,040,825`；
  进函数时 `next_step_clock=0` ⇒ 第②块**整块跳过** ⇒ 出函数时 `next_step_clock=5,040,825`，队列仍空。
- **第二次调用（第二步）**：`step_time=0.003536 s` → `step_clock=5,070,711`；
  此时 `next_step_clock=5,040,825` ⇒ 第②块执行；同向故跳过换向判断，
  `queue_append()`（`:498-500`）把 `5,040,825` 写进 `qstep[]` 并清空格子
  ⇒ 出函数时 `next_step_clock=5,070,711`。两次的差别只在第②块「跳过 → 执行」。
- **换向保护**（`:517-525`）：方向变了且两步挨得太近（`< SDS_FILTER_TIME`）时
  `next_step_clock=0` 撤销上一步并 return；能反悔的前提是它**还没进队列**，这正是「延迟一格入队」的原因。
- `last_step_clock` 两次都是 0（函数里没有给它赋值的语句）；
  `queue_flush` 才把 `qstep[]` 里的绝对时刻改写成「每隔多久」。
> 首步精确值含 `calc_last_step_print_time()` 的 `-.5` 半 tick 补偿，用来抵消 `(uint64_t)` 截断。

## 关键发现

1. **第一个 step 的时刻由 `half_step` 与加速度决定，与 F 无关**：`x(t)=½at²` 求
   `½·step_dist` 的根 → 0.002041 s，加 0.25 s = 5,040,825 tick。改 `microsteps` 才动它。
2. **「绝对时间戳」与「步间间隔」是两个不同的量**：5040825 是首步绝对时刻，
   5000 是匀速段相邻两步的间隔；前者由起步动力学定，后者由巡航速度定。
3. **`add` 不是加速度，而是 `interval` 的逐阶增量**：符号直接判定加 / 匀 / 减，
   这也是 MCU 只需整数加法就能复现变速的原因。

3. 只把 `F3000` 改成 `F6000`：(a) 匀速段 `interval`？(b) 首条 5040825 变不变？为什么？

### 参考答案

1. ① 上位机定死时间轴、MCU 只到点翻转；② 绝对时间戳、非延时；③ ≥0.25 s 提前量，
   是丢步 / 抖动 / 提前减速 / 输入停滞的共同根源。
2. `50` / `0.016667, 0.983333, 0.016667` / `0.25，无点位序列` / `0.25 ms` /
   `next+=interval; interval+=add`。数值依据见 `docs/dataflow.md` 第 4 节。
3. (a) **2500**（实测 `count=3731`）；(b) **不变**，仍 5040825。
   首步由 `half_step=0.00625 mm`、`a=3000` 定：`t=0.002041 s = 40825 tick`，
   加 `print_time 0.25 s`（5,000,000 tick）= 5,040,825，与 F 无关。
