## 做了什么

### 1. 知识点

**A. `Move` 与 IK（1-2 收尾）**

1. `Move` 只描述笛卡尔空间的一条线段 + 速度上限，与运动学无关：同一段
   `G1 X100 Y100 F6000` 在 cartesian 与 corexy 下字段一字不差。
2. `axes_r` 是单位方向余弦、`move_d` 是 XYZ 三维长度（不含 E），满足
   `axes_d[i] = axes_r[i] × move_d`；`min_move_t = move_d / min(speed, max_velocity)`。
3. 速度量一律用平方存：`max_cruise_v2`、`max_start_v2`、`delta_v2 = 2·move_d·accel`，
   直到 `set_junction` 才开方并算三段时长。
4. 运动学只在两处介入：① `check_move` 可改 `accel / max_cruise_v2`（Z 轴限速走
   `limit_speed`）；② `setup_itersolve` 给每个电机注册 `calc_position_cb`。
5. IK 是「位置公式」不是「批量换算」：`t → q` 单点函数，被 `itersolve.c:72` 在
   求根循环里反复调用；三家公式 cartesian `q=x/y/z`、corexy `q₊=x+y, q₋=x−y`、
   delta `q=√(arm²−(tx−x)²−(ty−y)²)+z`。

**B. 前瞻 flush 两趟扫描（1-3 前半）**

6. **flush 只有两趟，没有迭代**：逆向一趟定上界（`:146-169`），正向一趟传播压低
  （`:174-181`），O(n) 即自洽。
7. 交界速度在 `add_move` 时一次算好，存进**后一段**的 `max_start_v2`（`:97`）；
   `Move` 没有 `end_v2` 字段，前一段的出口速度靠 `junction_info` 里的
   `next_start_v2` 正向传递。
8. 巡航上限三个来源：距离解析解 `(start_v2+reachable)/2`（「加减速 ≤ 行程」的
   解析形式）、`max_cruise_v2`、`peak_cruise_v2`。
9. **MCR 只进巡航通道**：`mcr_delta_v2 = 2·s·a(1−r)`，`peak = (mcr_start +
   reachable_mcr)/2`，等价于「巡航段 ≥ r·行程」；它从不参与 start 速度。
10. lazy flush 只下发已固定的前缀：`flush_count = i + pending_cv2_assign`
   （`:160-162`）；实测 3 段入队只放出前 2 段。
11. `junction_deviation` 由 SCV 反推（`:534-537`），90° 拐角时 `v = SCV` 恰好成立；
   `max_start_v2` 的原料只有两段方向 + `max_accel` + `SCV`。

### 3. 实测

**实验一（IK 对照）**：`G1 X100 Y100 F6000`，只换 `[printer] kinematics`：

| 项 | cartesian | corexy |
| -- | -- | -- |
| `Move` 字段 | `move_d=141.421356`，`axes_r=[0.7071,0.7071,0,0]` | 完全相同 |
| 参与运动电机 | X 与 Y | 只有 `x+y`，`x−y` 零步 |
| 每轴步数 | 各 8000 | 16000 |
| 匀速 `interval` | 3536 tick = 70.71 mm/s | 1768 tick = 141.42 mm/s |
| 首步 `interval` | 5048549 | 5034329 |

验算：`8000 = 100×80`；`16000 = (100+100)×80`；带速 `v₊ = vx+vy`；首步由
`half_step` 与带加速度 `3000×1.4142` 决定，与 F 无关。

**实验二（前瞻）**：`sim/lab/lookahead.gcode`，路径 `X50 → Y2 → X150`，F6000：

| 配置 | 2 mm 段 `cruise_v` | `cruise_t` | 拐角 `max_start_v2` |
| -- | -- | -- | -- |
| 默认（`mcr=0.5`, `scv=5`） | 55.0000 | 0.018182 | 25 |
| `MINIMUM_CRUISE_RATIO=0` | 77.6209（纯三角） | 0 | 25 |
| `SQUARE_CORNER_VELOCITY=10` | 55.6776 | 0.017961 | 100 |

验算：距离项 `(25+12025)/2 = 6025 → 77.62`；MCR 项 `(25+6025)/2 = 3025 → 55`；
`cruise_t = (2 − 0.5 − 0.5)/55 = 0.018182`，即巡航恰占 50% 行程；
90° 拐角 `v² = 2.4142 × jd × a = scv²`。

## 关键发现

1. **规划层与运动学解耦**：换 CoreXY 后 `Move` 一字不差，差异全部推后到每个电机
   各自的 IK 公式；Klipper 没有独立逆解层，IK 是被求根循环反复调用的单点函数。
2. **前瞻是两趟扫描而非迭代**：上界在入队时定好（拐角存进后一段 `max_start_v2`），
   flush 逆向取 `min` 定上界、正向压低传播；lazy 模式只下发已固定的前缀。
3. **速度参数语义分层**：SCV 就是 90° 拐角速度（`jd` 由它反推）；MCR 等价于
   「强制巡航占比 r」且只影响段内轮廓；同一个 `F` 在不同运动学下不是同一个
   电机速度。

## 自测

1. `junction_info[i]` 的 4 元组第 4 项是什么？`max_start_v2` 由谁、何时、写进哪一段？
2. 2 mm 段 `cruise_v=55` 的两个来源？90° 拐角速度为何恰好等于 `SCV`？
3. `SCV` 从 5 改 10：哪些量变、哪些不变？递推链上第一处变化发生在哪一行？

### 参考答案

1. 是**下一段**的 `start_v2`（= 本段 `end_v2`）；`max_start_v2` 由 `calc_junction`
   在 `add_move:190` 时算好、经 `:97` 写进**后一段**；第一段没人改写，保持 0
  （从静止起步）。`set_junction` 第三参用的就是 `next_start_v2`。
2. 距离：`(sv²+ev²+2as)/2 = 6025 → 77.62`（`:164`）；MCR：
   `(25+6025)/2 = 3025 → 55`（`:163-165`），取 min。90° 时 `sin=cos=√2/2`，
   `R_jd = 2.4142`，而 `jd = scv²(√2−1)/a`，两者相乘恰得 `v² = scv²`。
3. 变：`max_start_v2`（25→100）、两段交界速度（5→10）、2 mm 段 `cruise_v`
  （55→55.68）。不变：`move_d`、`delta_v2`、巡航 F 上限。第一处变化在
   `add_move:190 calc_junction`（入队时刻），不在 flush 里。
